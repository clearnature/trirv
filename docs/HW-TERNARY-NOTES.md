# HW-TERNARY-NOTES —— 三值硬件底层边界研究备忘

状态：研究备忘（不约束当前批次；硬件期 = ADR-003 E 阶梯之后的选型输入）
起源：2026-11-25 架构讨论（用户）——「微机原理是多层抽象黑盒；我们不关心
物理电路，关心硬件的逻辑抽象边界；漏电/隧穿是资源不是缺陷」。

## 一、抽象栈与「可拥有边界」

```
物理参数层（电压/相位/隧穿概率/谐振相位）  ← 熵与精度的矿（见 §三）
器件层（晶体管 / MTJ / 约瑟夫森结）        ← 物理实现选择（华为三值电路专利在此层）
微架构层（微码/流水线）                    ← 厂商黑盒；有破解先例（decap/侧信道）；
                                             RISC-V = ISA+RTL 全公开的制度化先例
ISA 层（机器码）＝ 抽象契约                ★ 逻辑抽象的最低拥有点
虚拟硬件层（TriRV VM / PyVM / CVM）        ★ TriRV 的完整定义域（TriRV ISA = 我们的机器码）
方言/编译器层（C 三值本征 / wasm 方言）    ★ 拥有
libc / 软件层（musl_tri）                  ★ 拥有
```

- **机器码（ISA）就是抽象层**——软件可见的第一层契约；TriRV 拥有自己的
  一整层（102 条指令，ADR-01 冻结），不需要在别人的 ISA 下钻。
- 微码 = 厂商私产（x86 封闭；MCU 无微码暴露）→ 不是可行边界。
- **可真实掌握的物理层以下边界 = FPGA 软核**：自写 trit 数据通路。
  **路线澄清（用户 2026-11-25）**：我们选择的路线 = **243 虚拟逻辑地址
  翻译模型**（tryte 编址、cell = 5 trit）——「一个 trit 用 2 bit 编码、
  4 态用 3 态」**不是我们的路线**（那是二进制思维的又一次混入）。硬件
  期的物理实现形态是硬件期工程问题，不属于路线定义。

## 二、物理层要点（用户的直觉 × 业界实证）

- 「晶体管只能测 2 个电压」是工程选择不是物理必然。规模化多电平先例：
  NAND QLC（每单元 **16 电平**，存 4 bit）、PAM-4 串行（4 电平）。
  代价账：电平↑ → 噪声裕度↓ → ECC/速度/模拟精度工程↑——**经济学问题
  非逻辑可能性问题**。
- **漏电/量子隧穿 = 熵资源**（TRNG 产业实证）：栅极隧穿/雪崩噪声/热噪声
  是商用真随机数芯片的经典熵源；Intel RDRAND 物理基础 = 热噪声。
  「把缺陷当资源」的翻转是该领域标准思维。
- 约瑟夫森结：超导 SFQ（单磁通量子）逻辑天然脉冲计数范式，适合多值
  编码；需低温——硬件期物理选型菜单项。

## 四、TriRV 映射（不越层）

- **三值熵源空白点**：商用熵源全为二进制量化（噪声 → 比较器切 0/1）；
  trit = 3 电平量化承载 log₂3 ≈ 1.58 bit 熵/次——三电平量化噪声源
  （谐振相位三阈值切割 / 隧穿三窗口）**未见有人做**，是用户背景
  （谐振器）可拥有的研究方向。
- **ISA 冻结已为硬件期付费**：`SYS_GETRANDOM`（当前确定性 xorshift，
  ADR-09 口径）的 ABI 已在——硬件期把三值熵源接到 ABI 后面，上层零改动。
- `LIT1/LIT2`（trit 后继/前驱）= 华为自增/自减三值逻辑电路专利的
  **ISA 语义等价物**（2026-11-23 批次落地）。专利贡献在晶体管电路层，
  我们的贡献在 ISA/软件栈层——硬件期互引素材，现在无需模拟其电路。
- 硬件期物理实现形态挂 ADR-003 E 阶梯之后（路线 = 243 虚拟逻辑地址
  翻译模型，见 §一 澄清）。

## 五、范围纪律

## 六、BIOS/SBI 固件底层掌握程度评估（2026-11-25，用户问题）

规划已掌握的固件资产：udk fork（**ubios** = BIOS/UEFI 替代）、
rustsbi fork（SBI 运行时服务）、TSBI（三值 SBI 规格产出）、
TernixOS boot 层（boot/udk + boot/rustsbi 子模块）。

### RISC-V 启动栈逐层掌控度

| 层 | 运行特权 | 掌控方 | 程度 |
|---|---|---|---|
| SoC Mask ROM + DDR init blob | — | SoC 厂商（TH1520 等） | ✗ 不可控（黑盒 blob）——QEMU/FPGA 靶上**归零** |
| FSBL/ZSBL | M 态 | 厂商提供源码，可改 | ◑ 源码级可改 |
| **SBI**（rustsbi/TSBI） | **M 态 = 机器最高特权** | **我们（fork 全源码）** | ✓✓ 完全掌控：可改全部实现 + 定义**自定义 SBI 扩展**（TSBI 调用面） |
| **UEFI/BIOS 层**（ubios） | 启动服务/运行时服务 | **我们（fork 全源码）** | ✓✓ 完全掌控 |
| Bootloader（U-Boot/GRUB） | S 态 | 开源，可改 | ✓ 完全掌控 |
| OS（TernixOS 微内核+HAL） | S/U 态 | 我们 | ✓✓ |

### 「掌握到什么程度」的结论

1. **源码级全栈掌控**：从 SBI 到 OS 的每一行都可读、可改、可重建——
   Mask ROM 之上的整条启动链没有黑盒。
2. **SBI = M 态 = 机器最高特权层**：掌管全部 trap/时钟/IPI/HSM/复位/
   PMU，且**可定义自定义扩展**——硬件暴露白名单的落点就在这一层：
   「哪些物理资源透传给三进制世界」= 我们在 TSBI/ubios 里写的白名单
   （与用户「底层二进制硬件暴露白名单」规划直接闭环）。
3. **TriRV 虚拟硬件上更彻底**：固件层本身就是我们定义的
   （`trirv_firmware` + 批次 5 定时器/ISR 向量已落地）——VM 的
   「BIOS/SBI」= 我们的启动契约，天然 100% 掌控，无 Mask ROM 概念。
4. **边界（唯一不可控点）**：真实 SoC 的 Mask ROM/初始化 blob；
   硬件期靶选（QEMU/FPGA 软核）即完全消除。x86 BIOS/签名启动链
   不在路线内。

### 与白名单规划的关系

硬件暴露白名单（另立项）的三层落点：
- **SBI/TSBI 扩展**（M 态）：物理资源（熵源/时钟/外设）透传的白名单——
  本备忘 §四 的三值熵源接 `SYS_GETRANDOM` 类 ABI，落点即此
- **ubios 启动服务**：引导期硬件初始化与移交的白名单
- **VM 边界**：二进制语义拦截/放行（安全红线所在，ADR-003 前置）
