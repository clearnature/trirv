# Wasm 前端（路径 A）—— 设计说明与实测
状态：进行中（ADR-32 批次 2.15 统一补标——该文档未逐份定稿，收官时更新）

> 目标不是建生态，而是回答一个问题：**三进制机器能不能跑栈式字节码？**
> 答案：能。代价是多少，下面全部是实测，不是估计。

## 一、为什么是"翻译器"而不是"复用 wamrc"

WAMR 的 `wamrc`、Wasmi、Wasmer、Wasmtime 输出的都是 **RV32/RV64 二进制机器码**。
TriRV 的指令字是 20 trit 定长、opcode 是 3 trit —— 一个字节都不通。

这不是配置问题，是定义问题：和"RISC-V 的 `.elf` 在 `trirv_vm` 上跑不了"完全同源。
所以路径只有两条：

| 路径 | 做法 | 代价 | 结论 |
|---|---|---|---|
| A | 自己写 Wasm 字节码 → TriRV 汇编 | 小，栈到栈直译 | **本次实施** |
| B | fork LLVM RISC-V 后端，只换编码层 | 月级，但从 C/Wasm 都能进来 | 后期 |
| C | 硬件直接实现栈 CPU | 流水线难做、生态为零 | 否决 |

路径 A 的价值在于：**用最短的路证明可行性**，并顺手把三进制的边界问题全部撞一遍。

## 二、内存模型：规格差异与真实成本

Wasm 按 byte（8 bit，256 个值）编址，TriRV 按 tryte（5 trit，**243 个值**）编址。
`2^8 = 256 > 3^5 = 243`。

**这不是"代价"，是定义。** 基数不同，能表示的范围自然不同；而宽度本身就是定义
出来的东西 —— 想要 256 个值，6 trit（729）就够，想要更多再加 trit。所以
"谁装得多"推不出任何工程结论，把它记进成本账是口径错误。真正要计量的只有一本账：
**把 wasm 的二进制语义搬到三进制机器上，必须多花多少条指令。**

本切片选"1 wasm byte = 1 tryte，地址零偏移"（wasm 地址 == TriRV 地址），
理由是**寻址完全直通、零换算指令**。下表是**定义对照**，不是"损失清单"：

| 类型 | Wasm 定义 | 本切片定义 | 是否保真 | 保真的代价（按指令计） |
|---|---|---|---|---|
| i8 | mod 2^8 | 1 tryte（5 trit） | 值域内保真 | store/load 各一次边界判定 |
| i16 | mod 2^16 | 未支持 | — | 需显式 mod 2^16 |
| i32（寄存器） | mod 2^32 | 45 trit + 显式规整 | **保真** | add/sub 各 2 条、mul 11 条 |
| i32（内存） | 4 byte | 4 tryte = 平衡 243 位 | 4 byte 视图内保真 | store 4 次归位、load 4 次 LB |
| i64 | mod 2^64 | 未支持 | — | 45 trit 装得下，回绕另计 |
| f32（P3） | IEEE binary32 | **TF20**（1+5+14 trit）三档原生格式 | 档位自主定义，非 IEEE 逐位 | 常量编译期穿透（IEEE→TF raw）；四则/sqrt/比较/load/store 直通 F 指令 |
| f64（P3） | IEEE binary64 | **TF45**（1+10+34 trit）三档原生格式 | 档位自主定义，非 IEEE 逐位 | 同上；尾数 34 trit，指数无 double 值域约束 |

> 浮点 **不照搬 IEEE 语义**：IEEE 位模式只作为 wasm 字节码的外部输入编码，在编译期
> 由宿主解码成 host double 再量化成 TF raw；运行时 VM 只见 TF raw，只跑三进制浮点
> 指令。舍入按三档自主定义计，不声称"零损失"。详见 `TERNARY_FLOAT_PROPOSAL.md` §5.2/§5.3。

三条要点，全部只谈指令，不谈"位"：

- **i32 的 32-bit 回绕是二进制定义，不是三进制的缺陷。**
  `243⁴ = 3.49×10⁹ < 2³²` 只说明 4 tryte 装不下 2³² 个**互不相同**的值；
  但换更宽也救不了 —— 2³² 不是 3 的幂，**任何三进制宽度都无法无损表示 i32 全域**。
  所以这里不存在"少几个值"式的亏损，只有一条选择：花不花指令去模拟 mod 2^32。
  选了花，成本就是那条规整指令。
- **i32 回绕的价钱按指令算**：add/sub 一次 ±2^32 条件修正（便宜），
  mul 逃不掉一次 `DIV`（`~150ns`，72 步逐位恢复除法）。这叫模拟税，不叫位宽税。
- **i64 只需 41 trit 单寄存器装下** —— 这同样不是"三进制赢了"，只是定义不同；
  真正的账仍然是要不要花指令模拟 mod 2^64，与能装多少位无关。

## 三、代码生成

### 帧布局

```
fp (= s0) + 0            局部变量 0 .. nlocals-1   （各 1 word = 9 tryte）
fp + nlocals*9 + j*9     操作数栈槽 j
```

操作数栈槽按**静态高度**寻址，运行时不动 sp —— 高度在翻译期就能算出来，
所以每个 `push`/`pop` 就是一条 `SW`/`LW`。

### 寄存器

| 寄存器 | 用途 |
|---|---|
| s0 / fp | 帧指针 |
| ra | 返回地址 |
| sp | 栈顶（每个函数只调一次） |
| **t0–t6** | **操作数栈驻留池**：槽 j 的规范位置就是 t{j}（j < 7） |
| **s1 / s2** | **局部变量驻留**：仅 leaf 函数，按 `local.set` 频次挑最热的 2 个 |
| s3–s8 | 指令内部临时：s7/s8 条件类、s6 地址常数、s5 余数、s3/s4 借用 |
| **s9 / s10 / s11** | **−2^31 / 2^32 / 2^31**，`_start` 装好，wasm 代码只读 |

三条不变量，缺一条就会出隐蔽错误：

1. **操作数栈不落内存**。`push`/`pop` 走影子栈，只有控制流汇合点才 `spill_all()`，
   所以每个标签处的栈状态恒为"全在内存"，分支合流无歧义。
2. **临时寄存器与驻留池隔离**。运算内部只用 s3–s8，绝不用 t0–t6 —— 否则
   `wrap` 里一次 `SLT t3` 就会踩掉栈第 3 项。
3. **局部变量只在 leaf 函数驻留**。有 `call` 时被调用者会破坏 s1/s2，
   所以 `has_call()` 为真的函数直接放弃这层优化（退化为访存，语义不变）。

`s9`–`s11` 常驻是刻意的：`i32.add` 的每一次回绕都要用 2^31 和 2^32，
放在寄存器里省掉每次 5 条指令的常数构造。

### 就地更新（`local.get x … op … local.set x`）

栈机最贵的是"值从 local 搬到栈、算完再搬回 local"。识别这个四指令模式后
直接写成 `ADD s1, s1, s2`（结果落回 x 的寄存器），两头搬移全免：

```
local.get 1  →  零指令（槽 0 直接别名 s1）
local.get 2  →  零指令（槽 1 别名 s2）
i32.add      →  ADD s1, s1, s2   + wrap
local.set 1  →  零指令（结果已在 s1）
```

`inline_target()` 只在三个条件同时成立时才动手，否则退回通用路径：
目标 local 有寄存器、左操作数的槽里放的就是该寄存器本身、下一条确实是 `local.set`。


### 指令映射要点

| Wasm | TriRV 实现 | 备注 |
|---|---|---|
| `i32.add/sub` | `ADD` + 两条 ±2^31 判定 | 越界最多一次，无需循环 |
| `i32.mul` | `MUL` + `DIV/MUL/SUB` 取模 | 回绕税，~11 条 |
| `i32.div_u/rem_u` | 负数先 `+2^32` 转无符号 | 三进制没有免费的无符号解释 |
| 所有比较 | `SLT` / `SUB`+`SLT`+`SUB` | **`XORI 1` 不能当逻辑取反**：三进制 XOR 是逐位模 3 加 |
| `i32.store` | 拆 4 个平衡 243 位，每位一次无分支归位 | 修正量 = 243×((d<122)+(d<−121)−1) |
| `i32.load` | 4 次 `LB` + `SLLI 5/10/15` | `LB` 自带 5-trit 符号扩展，正好等于平衡位 |
| `if`/`br` | 条件分支只跨 1 条，接 `JAL` 跳远处 | 规避 B 型立即数 ±1093 的限制 |
| `i32.and/or/xor` | 32 次「比较 2^k + 条件减法」拆位，位级用 `TAND`/`TOR`/`TMAX-TMIN` 合成 | 见 §三·五，**这是整张表里最贵的一项** |
| `i32.shl/shr` | 乘除 2^k，`shl` 走 `wrap_mul` 取模 | 移位量先按无符号取再 `% 32` |
| `i32.rotl/rotr` | 两段互不重叠的位，`shl` 段 + `shr` 段**直接相加** | 不需要 OR，省掉一次拆位 |
| `clz/ctz/popcnt` | 同一条走查，换累加方式 | `ctz` 靠"高位先写、低位覆盖"取最低位 |

### 五、二进制位从哪来（本切片最硬的一块）

三进制寄存器里**不存在二进制位**。第 k 位只能这样取：

```
残差 r 从值本身出发，拿 2^k 逐个比；r >= 2^k 则该位为 1，同时 r -= 2^k
```

这就是二进制长除法的展开式，但**一次 DIV 都不用** —— 全是 `SLT` + `SUB`。
`2^k` 表（32 个字）放数据段，`gp` 常驻指向它，一位一条 `LW`。

必须**从高位往低位走**：剥掉第 k 位后残差 < 2^k，下一位的比较才有意义。
反过来（低位先走）要先把低位移出去，那就得除法了 —— 这一点踩过坑，见 §五·实测。

拆出两个 0/1 标志位之后，合成几乎是免费的（0/1 值域内 Kleene 逻辑退化为布尔逻辑）：

| 运算 | 合成方式 | 指令 |
|---|---|---|
| `and` | `TOR ta, tb` 再取反 = 1 − max | 2 |
| `or` | `TAND ta, tb` 再取反 = 1 − min | 2 |
| `xor` | `\|ta − tb\|` = `TMAX` − `TMIN` | 4 |

## 四、不支持清单（都是显式 `UNSUPPORTED`，绝不静默出错）

| 特性 | 原因 |
|---|---|
| i16 存取 | 2 tryte = ±29524，与 wasm 的 ±32768 错位，语义会静默错 |
| i64 | 未实现 |
| f32 / f64 的 min/max/neg/abs/ceil/floor/trunc/nearest/copysign | 超出 P3 范围（已实现 const/四则/sqrt/比较/load/store/局部变量） |
| 浮点形参、float↔int 转换（convert/trunc） | 需 freg 传参 ABI / wasm 舍入语义，留 P4 |
| `br_table`、`call_indirect`、table | 跳转表/函数指针 |
| 带结果的 block（blocktype ≠ 空） | 需要移动栈值到目标高度 |
| 形参 > 8、多返回值 | 栈传参未实现 |

## 五、实测

### 功能

`trirv_wasm_e2e.py`：**93/93 PASS**
三路对比：参考解释器（Python 直接跑栈式字节码）× TriRV Python VM × TriRV C VM，
逐例比对返回值 + stdout 字节，全部一致。

覆盖：加减乘除余（含溢出与负数）、无符号比较全家桶、`eqz`、
block/loop/if/br/br_if/return/递归 `fib(12)`、`select`、
i32 内存读写（含 ±1.7e9 边界）、`store8`/`load8_s`/`load8_u`、
data 段 + 导入 `print`（hello world 输出中文，两套 VM 字节一致）、
**位运算 35 例**（and/or/xor 含负数与 2^31 边界、shl/shr_s/shr_u、rotl/rotr 含 0 位、
clz/ctz/popcnt 含 0 与全 1、FNV-1a 哈希一段内存字节的端到端）。

### 位运算的真实代价（`bench_bitops.py`）

单条位运算的静态指令数（相对 `i32.add` 的 8 条）：

```
i32.and      372 条     46x
i32.or       372 条     46x
i32.xor      436 条     54x
i32.shl       28 条      4x
i32.shr_s/u   28 条      4x
i32.rotl/rotr 46 条      6x
i32.clz      197 条
i32.ctz/popcnt 165 条
```

位运算密集循环（`h = (h ^ i) * 16777619`，20000 轮，C VM）：
**405 步/轮，15.9ns/步**，几乎全部花在那次 xor 的 32 轮拆位上。

**怎么读这组数**：这不是"编译器写得差"，是**基数转换的物理成本**。
二进制机器上 `x & y` 是一条门电路；三进制机器上要先知道"哪一位"，
而"第 k 位"这个概念本身就得靠 32 次比较才能问出来。
真要压下去只有两条路（都需要改 ISA，见 `ternary-isa-design.md` §5.1）。


### 性能（求和 1..100000，C VM 计时，每项 3 次取最好）

三个对照，区别只在"要不要付 i32 语义税"：

```
                     静态指令     动态步数      墙钟      单步成本
wasm 直译 (驻留)        92     2,245,770   17.4ms     7.7ns
C 寄存器 (int=45trit)   20       500,017    5.8ms    11.6ns
C 寄存器 (手写 i32)     62     1,500,031   12.0ms     8.0ns
```

| 对照 | 动态步数比 | 墙钟比 | 说明 |
|---|---:|---:|---|
| wasm / C(45 trit) | 4.49× | 2.99× | **含语义税**，不是对等比较 |
| wasm / C(i32) | **1.50×** | **1.45×** | 公平对照，两边都做 mod 2^32 归正 |

**怎么读这组数**：C 的 `int` 是 45 trit 不截断，wasm 的 `i32` 每次加法都要回绕，
拿前者比后者等于让 C 免掉一半工作。让 C 也手写两条 `±2^32` 修正后，
差距从 4.49× 收到 **1.50×** —— 也就是说，原先看似"栈机太慢"的部分，
大头是 i32 语义税，栈机本身的开销只有 1.5 倍。

单步成本 7.7ns vs 8.0ns 说明 C VM 本身没有变慢，差距全在指令条数。

顺带一个语义差异（**不是 bug，是两套定义各自正确**）：同一段求和，wasm 结果按
mod 2^32 回绕到 `705082704`，C 的 `int` 是 45 trit 不截断，得 `5000050000`。
两边 `exit` 的低 8 位都是 80。这说明"值域"是定义层的事——不存在哪个更"对"，
只存在"这段外来语义要不要模拟、模拟要花几条指令"。

## 八、9.4 架构裁定：wasm 浮点 = soft-float（P4 路线，2026-11-24 立项）

**定义层发现（不可回避）**：wasm f32/f64 的值域是**二进有理数**（m×2^k），
TF 三进浮点是三进有理数（m×3^k）——2 与 3 互素 ⇒ 绝大多数 f32/f64 值
（0.5、0.1 等一切非整数）在 TF 中**不可精确表示**；现有编译期「IEEE 位模式
穿透成 TF raw」本质是舍入。spec 浮点断言（f32.wast 等）要求 **IEEE 位级
精确**（含 NaN payload/次正规）——TF 直算路线结构性不可达，这不是工程缺口
而是定义层差异（与「2^8>3^5」同一诚实口径）。

**裁定（P4 路线）**：wasm 浮点 = **soft-float**——IEEE 位模式作为 i32 数据
存取（复用 9.9 前的整数面），全部浮点运算在整数 ALU 上软件模拟（比较用
符号-幅值→偏置变换的整数比较法；abs/neg/copysign/min/max/ceil/floor/
trunc/nearest 为纯位操作；add/sub/mul/div/sqrt 为 softfloat 核心算法，
参照 musl math/soft-fp 移植到 trirv C 子集 → 预编译 .trvo 运行时库，
翻译器 emit 调用）。ISA 浮点指令（TF 语义）服务原生 TF 用例，与 wasm
soft-float 正交——不在 ISA 层加 IEEE 语义指令（ISA 冻结边界）。

**分批落地**：P4a 位操作九件（abs/neg/copysign/min/max/ceil/floor/trunc/
nearest——整数位技巧全精确）→ P4b softfp 加减乘除核心 → P4c sqrt/convert/
trunc_sat → 与 9.5 convert/trunc 合流 → 9.6 多参与多返回 → 9.7 i64（mod
2^64 同 soft 路线评估）→ 9.9 Barrett 约减（微基准）。现 P3（TF raw 面板）
保留给非 spec 场景，P4 落地后 spec 路径切 P4。

**Why:** 路线由定义层差异决定，非偏好；soft-float 是栈机到任意宿主的
标准诚实做法（musl/SoftFloat 同源）。
**How to apply:** 9.4 起浮点相关 spec 断言以 soft-float 位精确为准；
TF 直算路径不再对 spec 基线计数。

## 九、算术层拍板：纯三值无回绕（2026-11-25，取代 §八 的 int 部分）

用户裁定：「三进制有自己的全套标准，32 位对我们是无效的」。
wasm 方言整数类型 = **原生 45-trit word**，无回绕、无 32 位概念、无无符号视图。

**删除面（仿真层整体退役）**：
- `wrap`/`to_unsigned`/2^k 表（gp/P2）/32 轮拆位走查（gen_bitop 的
  and/or/xor 各 ~380 条 → **1 条 TAND/TOR/XOR**）
- i32.add/sub 各 2 条回绕修正 → **1 条 ADD/SUB**；mul 11 条 → **1 条 MUL**
- 移位 ×/÷ 2^k 链 → **原生 SLL/SRA（×3^k 三进移位）**
- lt_u/无符号比较族 → 原生 SLT 符号比较
- clz/ctz/popcnt/rotl/rotr：二进制位概念 → 方言删（三元位运算 = 逐 trit）
- **9.7 i64 / 9.8 i16 / 9.9 Barrett 全部溶解**：原生 word 天然覆盖 64 位
  值域；小类型 = tryte；无回绕则 Barrett 无意义

**内存层（§十 定版）**：cell = tryte（0..242）、word = 9 tryte 原生
（= VM `_store_word` 口径）、地址 1:1 零翻译——i32.store/load 发射
**1 条 SW/LW**、store8/load8 = **1 条 SB/LBU**（访存仿真层整体删除，
旧 digit 拆装 ~34 条 → 1 条）。跨宽度别名 = 三元语义记档
（store8 写的 tryte 是 word 的某位 digit）。

**方言即标准（用户裁定 2026-11-25 二次确认）**：三进制值域
（tryte 0..242、word 45 trit）**就是全部标准**——不存在「255 装不下」：
我们根本不表示二进制字节值；「4 tryte 装不下 32 位」也不是容量问题
——旧 digit 拆装是在仿真不该仿真的东西，处置 = 删除而非修复。
二进制值域若要进入 = 加载器/地址翻译层的边界职责（另立项），
与核心 ABI、内存模型、翻译器无关。spec testsuite 仅作结构面练习
工具（block/loop/br/br_table/if/call/table 的翻译完成度），其
二进制语义断言与本方言**无关**（不是「NS 代价」，是不适用）。
FNV/CRC 类二进制算法不移植——三值算法是另一套（逐 trit 变体，
按需设计）。连续逻辑地址：word 45 trit，多大都能表示，无地址容量
问题。

**浮点注记**：§八 soft-float 裁定的动因（IEEE 位级精确）与本次同源
——纯三值口径下 f32/f64 算术 = **原生 TF 指令**（P3 面板回归），
IEEE↔TF 转换只在数据边界（encode/decode 已有）；spec 浮点断言 =
定义性 NS。§八的 soft-float 路线作废，9.4 的 min/max/abs/neg 在
TF 格式上是 sign-trit 操作（比 IEEE 位技巧简单得多），
ceil/floor/trunc = 基 3 阶码操作。

**Why:** 5-trit/243 的选型本就为对齐宿主地址翻译；byte 是二进制产物，
为其保真而把三元 ABI 永久变形（2-tryte 对）是付双重税（内存 ×2 +
每访存 ~20 条指令）买「另立项才需要」的兼容。纯三值口径下访存从
~34 条 → 1 条，算术从 ~380 条 → 1 条。
**How to apply:** 翻译器重构按本节删除面执行；e2e/spec 基线按新刻度
重 derive；TernixOS/上层软件以原生 word/tryte 语义编程。
