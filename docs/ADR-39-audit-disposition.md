## 二、澄清（审计判断需补上下文）

- **调度器 TRV_FORMAT=1 钉住**：这是 6.3a 的**已记录契约**（cc_backend 的消费方
  需要槽序词+汇编行 1:1 对应，trirv_cc_backend.py 注释在案）。TRV2 默认输出的
  回归覆盖由直调 trirv_cc 的套件承担（crt/musl_e2e/arch/amp 等约 30 套在
  b7b59d4 起的每次钩子全量跑 TRV2 产物）——准入③证据即此口径。审计指出
  的「走调度器的 21 套在测 TRV1」属实但不构成覆盖缺口；已在 ADR-17 执行
  记录中补注此口径说明。

## 三、采纳-待办（真实问题，列入台账按批处理）

- VM CLI：`-n/-a/-t/-o` atoi 无校验（0/负值 → 零长分配 UB）；进程退出码恒 0；
  guest argv 字节 %243 回绕（243–255）与静默截断；零页覆写 0–26 与 wasm
  数据段冲突——归入「VM CLI 健壮性」批（ADR-09 边界内，退出码语义变更需
  全量套件核对后动）。
- 步数耗尽与 exit 0 不可区分：CVM stderr 已带 halted=/步数= 字段，测试侧
  按需断言 halted；运行器级「halted=0 即 FAIL」选项待评估。
- 调试器：except 吞异常、`c` 无步限、`_slot_of` 忽略入参、容器解析与 _trvio
  重复——归调试器批。
- 二进制重建 mtime 只看单源文件（trirv_float.h 改动不触发）——归门禁批。
- 编译器定长缓冲写法（如 parse_type 曾有的 malloc(256) 族——别名分支已修，
  其余点位逐个过 ASAN）+ 45 个 exit() 双退出码口径（1=语法 2=UNSUPPORTED
  为既有约定，保持）——归解析器健壮性批。
- 审计「布局常量散落 4–8 文件」——属重构项，随 6.3b 虚拟磁盘面顺手收口
  （AMP 窗口/堆基址等已有双 VM 逐常量对齐的契约在守）。
